1项目定位与核心特性

CubeSandbox 是腾讯云开源的、面向 AI Agent 的高性能安全沙箱服务，基于 RustVMM + KVM 构建。它把每个沙箱做成一个独立的 MicroVM（微虚拟机）——拥有自己专属的 Linux 内核与硬件级隔离，同时通过「模板预快照 + RustVMM 恢复」与「XFS reflink 写时复制」两条核心技术路线，把冷启动压到 60ms 以内、单沙箱内存开销压到 5MB 以下，从而在安全性与密度之间取得平衡。

在 AI Agent 的执行形态中，它天然对应用例：Agent 调用工具 → 沙箱执行代码 → 返回结果。官方文档称之为「Agent-first」的基础设施，且对外暴露的是 E2B 兼容的 API——换一个环境变量即可从 E2B Cloud 无缝迁移。

六大核心特性

⚡
毫秒级启动
资源池 + 模板快照克隆，跳过全部冷启动开销：冷启动平均 <60ms；50 并发下 P95 90ms、P99 137ms。
🔒
硬件级隔离
每个沙箱在专属 MicroVM 中运行独立内核，无共享内核逃逸面，天然免疫容器逃逸类攻击。
🔌
E2B SDK 兼容
REST 层、数据面协议（Connect）、端口约定（49983/49999）全面对齐 E2B，改一个环境变量即可迁移。
📸
快照 / 克隆 / 回滚
CubeCoW 以 FICLONE 实现 O(1) 事件级快照；可对运行中沙箱打点、随时回滚到任意历史状态、或从某状态 fork 并行探索。
🛡️
零信任出口
eBPF 内核级隔离 + CubeEgress L7 出口代理：域名必须显式允许，密钥通过请求头注入，永远不进沙箱。
⏸️
自动暂停 / 恢复
空闲沙箱自动挂起（内存落盘为快照），下个请求到来时毫秒级唤醒，进一步提升密度与成本效率。

2总体架构

CubeSandbox 遵循 「控制面 / 数据面分离」 的架构哲学：

  • 控制面无状态：CubeAPI（Rust REST 网关）、CubeMaster（Go 集群调度器）、WebUI 与 Redis 构成控制面。所有协调状态收敛到 Redis——Redis 是沙箱元数据与生命周期事件的唯一事实来源，因此任一 CubeAPI / CubeMaster 实例都能服务任意请求，水平扩容极其简单。
  • 数据面节点本地：每个计算节点运行 Cubelet（Go）、CubeShim（Rust）、CubeHypervisor（Rust）、CubeCoW、CubeVS（eBPF）与 CubeEgress，负责本机沙箱的 VM 生命周期、存储、网络与安全执行。
  • 双通道请求模型：沙箱的「创建 / 销毁 / 暂停」等管理操作走控制面（REST → gRPC）；而「执行命令 / 文件读写」等数据面操作由 SDK 直接经 CubeProxy 路由到沙箱内 envd 守护进程，不经过控制面。

设计要点：「Stateless Control Plane」意味着所有协调（节点注册、沙箱路由表、生命周期事件、分布式锁）都走 Redis；而数据面组件全部 node-local，控制面升级或故障不会影响已在飞行中的沙箱。

3核心组件详解

下面按「控制面 → 节点数据面 → 存储 → 网络 → 配套」五个层面拆解每个组件的职责、入口与关键技术。

3.1 控制面：CubeAPI · CubeMaster

CubeAPIRust · :3000
E2B 兼容 REST API 网关，只做「翻译 + 转发」，不接触沙箱。
入口CubeAPI/src/main.rs → routes::build_router()；clap 解析 CLI。
路由/sandboxes、/v2/sandboxes、/logs、/timeout、/pause、/resume、/connect、/snapshots（长超时 240s）、/templates*、/volumes*。
中间件unified_auth（Bearer / X-API-Key，可回源 AUTH_CALLBACK_URL）+ 按 API Key 的令牌桶限流（governor）。
转发经 CubeMasterClient（reqwest）发 REST 到 CubeMaster :8089 的 /cube/* 路径，信封 {requestID, ret}。
职责环境变量黑名单校验、volume mount 拆分、lifecycle→auto_pause/auto_resume 翻译。
CubeMasterGo · :8089
集群大脑：调度、下发、元数据。不存本地状态。
入口CubeMaster/cmd/cubemaster → server.New()（gin）。路由分组 /cube/*（业务）、/internal/meta/*（节点）、/notify/*、/metrics。
gRPC 契约api/services/cubebox/v1/cubebox.proto —— service CubeboxMgr { Create / Destroy / List / Update / Exec / AppSnapshot / RollbackSandbox / … }。
调度器pkg/scheduler：least-select 选节点 + affinity 亲和/反亲和 + selctx。
创建流程解析模板 → 选节点 → gRPC 直连 Cubelet（host:9999）Create → 成功后向 Redis 写 bypass_host_proxy:<id> 路由元数据 + UPSERT MySQL sandbox_spec；失败则投递异步 DestroySandbox 清理任务。

3.2 数据面：Cubelet · CubeShim · CubeHypervisor · cube-agent

CubeletGo · :9999
每台物理机上的沙箱生命周期管家。
入口Cubelet/cmd/cubelet（fork 进独立 mount ns）→ services/server：内嵌 containerd v2 server + 自建 gRPC（CubeboxMgrServer，TCP :9999）+ operation :9998 + metrics :9966。
工作流引擎plugins/workflow 分步编排创建/销毁，步骤打点指标。
创建service.Create：镜像解析/拉取 → cubecow 卷准备 → tap 分配 → containerd 创建任务 → Cloud Hypervisor 启动 KVM MicroVM → 返回 sandboxID/IP/PortMappings。
上报masterclient 向 CubeMaster /internal/meta/nodes/register、/status 上报资源与版本矩阵。
CubeShimRust · Shim v2
把 MicroVM 包装成普通容器 runtime（io.containerd.cube.v2）。
入口CubeShim/shim/src/main.rs（containerd-shim-cube-rs）；子组件 cube-runtime 提供 snapshot/login CLI。
VM 桥接hypervisor/cube_hypervisor.rs：launch_vmm() 库模式创建 VmmInstance；create_vm()=VmCreate；模板冷启动走 restore_vm()；沙箱热启动走 resume_vm_cube()（VmResumeFromSnapshot）。
回滚先 VmDelete 删当前 VM，再从目标快照 VmResumeFromSnapshot，避免写内存到盘的 I/O。
就绪握手等待 NotifyEvent::VsockServerReady（经 SysCtrl 端口 0x680）才判定 vm ready。
CubeHypervisorRust (RustVMM)
基于 Cloud Hypervisor 深度定制的轻量 VMM。
两种形态独立二进制 cube-hypervisor（CLI 兼容 Cloud Hypervisor）+ 库模式 lib.rs（VmmInstance，CubeShim 同进程内嵌，mpsc 发 ApiRequest：VmCreate/VmRestore/VmPauseToSnapshot/VmResumeFromSnapshot）。
启动优化不冷启动——从模板内存快照直接恢复；内核 cmdline 极简（quiet、mitigations=off、clocksource=kvm-clock）；virtiofsd cache_policy=Never 减少 guest 页缓存。
SysCtrl 设备x86 PIO 0x680 / aarch64 MMIO：guest 上报 SYS_START / SYS_PANIC / SYS_VSOCK_SERVER。
加固seccomp 白名单最小化；fd 512 dup2 提前 expand_files 避免多线程创建锁竞争。
cube-agentRust · guest init
MicroVM 内 PID 1，源自 Kata Containers agent。
入口agent/src/main.rs，作为 /sbin/init 打包进 guest 镜像。
协议ttrpc over vsock（cid=3，端口 1024）；CreateContainer/StartContainer/ExecProcess 委托 rustjail 执行。
就绪握手RPC server 起来后写 SysCtrl 端口 0x680 置 SYS_VSOCK_SERVER 位，VMM 转发给 shim。
网络netlink.rs 配置 guest 侧接口/路由/ARP；device.rs 处理 PCI/virtio 热插拔。
快照 ABI：hypervisor 版本 28.0.0，快照 ABI SNAPSHOT_VERSION=1.0.3。恢复时严格校验 ch_version / kernel / CPU / 内存 / disks / pmems 一致性，并用 placeholder 补齐 pmem 避免设备布局错位。

3.3 存储与快照：CubeCoW

CubeCoWRust · FICLONE
Copy-on-Write 存储引擎，为 rootfs 卷与「内存卷」提供 O(1) 快照/克隆/回滚。
原理XFS reflink 上的 FICLONE ioctl（0x40049409）——快照只是共享 extent 的元数据操作，零字节拷贝。
扁平模型所有快照是独立文件，落在源卷目录下；删除任一快照不影响其他（对齐 dm-thin 语义）。
崩溃恢复无 ledger：启动时从目录布局重建元数据，清理孤儿文件。
FFIinclude/cubecow.h C 接口，Go 侧经 cgo 链接 -lcubecow。
存储调用方Cubelet · cgo
Cubelet/pkg/cubecow 是唯一生产调用方：创建沙箱时从模板卷 FICLONE 克隆 rootfs 与内存卷（memory_vol_url）。
快照语义VM 内存快照文件本身作为 cubecow 卷管理，实现「事件级快照 + 即时克隆 + 任意回滚」。
增量脏页快照只落自上次快照以来变化的匿名（脏）内存页，未变页面经 reflink 继续共享，写放大与快照体积双降。

3.4 网络：CubeVS · CubeEgress · CubeProxy · network-agent

CubeVSGo + eBPF
内核态网络数据面，替代 iptables/网桥/OVS。
三程序from_cube（TAP ingress：SNAT/策略/ARP 代理）、from_world（主机 NIC ingress：反向 NAT/端口映射）、from_envoy（cube-dev egress：CubeEgress 回包保留源 IP + 探针）。
隔离恒禁 10/8、172.16/12、192.168/16 等私网段——沙箱间永不互通。
会话双 Map 镜像 conntrack TCP 11 状态机，reaper 每 5s 回收。
DNS 学习dns_allow（反转域名 LPM）+ dns_query_track，命中后写 allow_out_v2（带 TTL）。
端口规划10000-19999 临时、20000-29999 CubeProxy、30000-65535 SNAT 源端口。
CubeEgressOpenResty(Lua)
每主机透明 L7 出口代理，所有出站 HTTP/HTTPS 不可绕过。
拦截listen 192.168.0.1:8080/8443 transparent reuseport + TPROXY + IP_TRANSPARENT 保源。
TLS MITMcert_signer.lua 用模板内置根 CA 按 SNI 动态签发叶证书。
策略access_phase.lua decide()：SNI/host/method/path/scheme first-match-wins，默认拒绝，bootstrap 未就绪一律 403（fail-closed）。
凭据注入action.inject 内联密钥，先 clear_header 再 set_header 防伪造头竞态，密钥仅以指纹进审计。
审计按主机 JSONL（access.jsonl），记录 dst/sni/method/path/注入指纹/安全事件。
CubeProxyOpenResty(Lua)
数据面反向代理，把 SDK 对沙箱的执行/文件请求路由到正确 VM。
路由模式Host-based：解析 <port>-<sandbox_id>.cube.app；Path-based：/sandbox/<id>/<port>/...。
后端解析sandbox_backend.lua 查 Redis bypass_host_proxy:<id>（本地 100m TTL 缓存），同节点直连 SandboxIP:port，跨节点转发 HostIP:hostPort。
流量令牌enforce_traffic_token：AllowPublicTraffic=false 时强制校验 e2b-traffic-access-token，否则 403。
流式envd_streaming_path_route.inc 对 Process/Start|Connect、Filesystem/WatchDir 关闭 proxy_buffering 支持服务端流。
admin:8082 端点供 lifecycle-manager 推送/拉取 last_active 状态；:8083 sidecar resume。
network-agentGo
节点本地网络编排，连接 Cubelet 与 CubeVS / CubeEgress。
APIEnsureNetwork / ReleaseNetwork / ReconcileNetwork（HTTP unix socket + 可选 gRPC + TAP fd 直传 fdserver）。
TAP 生命周期创建 TAP + AddTAPDevice + AttachFilter + SetSNATIPs。
IPAM从 192.168.0.0/18 分配沙箱地址；port_allocator 管理 20000-29999。
策略推送cubeegress_push.go 把沙箱 L7 策略（含内联凭证）推到本机 CubeEgress admin API。
恢复state_store.go 落盘 + 启动恢复。

5存储与快照机制

CubeSandbox 的存储模型围绕「模板 → 沙箱 → 快照」的层级展开，全部基于 XFS reflink：

# 存储层级关系
Template（只读基础镜像 + 冷启动内存快照）
  └── FICLONE ──→ Sandbox rootfs 卷（CoW，零拷贝克隆）
                      ├── FICLONE ──→ Snapshot A（事件级）
                      ├── FICLONE ──→ Snapshot B
                      └── FICLONE ──→ Clone 1 / Clone 2（fork 并行探索）

模板 → 沙箱 → 快照 三步流程

1
模板创建
OCI 镜像 → Buildkit 构建 rootfs → 冷启动 → 生成内存快照 → 注册为模板
→
2
沙箱启动
Cubelet 克隆模板 rootfs + 内存卷（CubeCoW，O(1)）→ CubeShim 从内存快照恢复 VM
→
3
增量快照
只写自上次快照以来的脏内存页；未变页面经 reflink 共享

为什么能这么快、这么省？

  • 不冷启动：沙箱不是从 BIOS/内核/init 一步步启动的，而是 直接恢复 模板的内存快照——绝大多数冷启动开销被彻底跳过。
  • 零拷贝克隆：FICLONE 是元数据级操作，克隆 rootfs 不复制任何字节，因此创建沙箱的时间几乎不随镜像大小增长。
  • 内存瘦身：virtiofsd cache_policy=Never 减少 guest 内核页缓存占用；内核参数 mitigations=off 关闭 CPU 缓解；单 vCPU + 512MB 默认规格。
  • 扁平快照：快照都是独立文件，删除任意一个不影响其他快照，不存在快照链递归问题。
核心洞察：「内存快照」其实是把 VM 的整块内存看作一个可 FICLONE 的卷——这让「事件级快照」「即时克隆」「任意回滚」都变成 O(1) 的文件系统操作，是 CubeSandbox 全部高级特性的地基。

6网络与安全模型

6.1 CubeVS 三层 eBPF 数据面

每个沙箱获得专属 TAP 设备，数据面转发全部在内核完成——无 iptables、无 Linux Bridge、无 OVS：

eBPF 程序挂载点方向职责
from_cubeTAP 的 TC ingress沙箱 → 主机SNAT、策略评估（LPM-trie）、DNS 拦截、ARP 代理、L7 重定向
from_world宿主机网卡 ingress外部 → 沙箱反向 NAT（查 ingress_sessions）、端口映射 DNAT、DNS A 记录学习
from_envoycube-dev 的 TC egress主机 → 沙箱CubeEgress 回包（保留远端源 IP，IP_TRANSPARENT）、就绪/存活探测

隔离与策略要点：

  • 恒定拒绝 10/8、127/8、169.254/16、172.16/12、192.168/16——沙箱之间、沙箱到私网永远不可达（单一路由即隔离）。
  • 策略顺序：allow_out_v2（LPM Trie）→ deny_out → 默认放行；策略按 TAP ifindex Hash-of-Maps，互不影响。
  • 域名级白名单由「DNS 学习」实现：DNS 查询命中允许域名后，响应中的 A 记录自动写入 allow_out_v2（带 TTL 过期）。
  • 对策略拒绝的 TCP 连接回 RST 而非静默丢包，保证 guest 内应用行为可预期。

6.2 CubeEgress 零信任出口

CubeVS 把需要 L7 检查的 80/443 流量 bpf_redirect 到 cubegw0，经 TPROXY 送达本机 CubeEgress（OpenResty）。沙箱模板内置了 CubeEgress 签发的根 CA，因此 HTTPS 也能被透明检查：

1
域过滤
SNI / host / method / path / scheme 规则，first-match-wins，默认拒绝
→
2
TLS MITM
cert_signer 按 SNI 动态签发叶证书，沙箱信任根 CA
→
3
凭据注入
内联 secret 以 Authorization 头注入，密钥永不进沙箱
→
4
审计
JSONL 审计日志，secret 仅以指纹记录
fail-closed：bootstrap 策略未就绪时 CubeEgress 一律返回 403（而非放行），避免出现「未配置即裸奔」的安全缺口。凭证注入仅发生在策略明确允许的域名上，杜绝把密钥发给任意站点的风险。

7SDK 与 E2B 兼容设计

CubeSandbox 提供 Python（0.6.0）、Node（0.3.0）、Go 三套 SDK，与 E2B 的兼容是多层、带桥接层的：

7.1 双通道架构

控制面requests.Session 直连 CubeAPI（:3000，X-API-Key 鉴权）：创建/连接/暂停/恢复/快照等管理操作
▼

7.2 兼容层细节

  • REST 形状兼容：端点与载荷对齐 E2B——官方 e2b-code-interpreter 包 + E2B_API_URL=http://127.0.0.1:3000 即可直接运行。
  • 命名兼容：envs 是 env_vars 的别名；lifecycle.on_timeout 语义对齐；SandboxInfo 提供 E2B 风格 snake_case 属性。
  • 网络策略兼容：E2B 的 per-host transform 映射（{"api.example.com": [{"transform": {...}}]}）自动展开为 CubeEgress Inject 规则（规则名 e2b-transform-<host>[-idx]，可审计）。
  • 卷兼容：volume_mounts={path: Volume|volumeID} dict 映射；省略 driver 走后端首个插件。
  • 端口/身份兼容：envd 端口 49983、Jupyter 49999、e2b-traffic-access-token 头——全部与 E2B 相同。
  • 命令通道复用：Commands.run 优先复用 E2B 的 e2b-connect 生成的 ProcessClient（protobuf RPC），无该依赖时退化为自带手写 Connect fallback。
一个已知例外：官方 e2b Python SDK 硬编码了 e2b.cloud，不能直接对接 CubeSandbox，必须使用 cubesandbox SDK 或裸 REST 调用。

8模板机制

模板是 CubeSandbox 的「快照化镜像」抽象：它不只包含 rootfs，还包含一份冷启动内存快照。模板的生命周期分三步：

1
Init 构建
tpl create-from-image：OCI 镜像 → Buildkit 构建 rootfs（可选 expose-port 49999/49983）
→
2
Boot & 快照
冷启动一次 → 生成内存快照 + 就绪探针（probe）
→
3
Deploy 注册
注册为 READY 模板，可被沙箱创建引用；tpl watch 等待状态
  • 模板别名（v0.6）：创建模板时可设置 alias，沙箱创建时直接指定别名。
  • 提交新模板：tpl commit --sandbox-id 可从运行中沙箱提交新模板，支持 --allow-internet-access / --allow-out-cidr / --deny-out-cidr 覆盖网络策略。
  • 版本矩阵：Dashboard 提供模板健康检查与组件版本矩阵，升级后可一眼看出哪些模板需要重建。
  • 兼容构建：CubeAPI /templates 提供 compat 构建，管理 E2B 兼容面。

MicroVM
精简微虚拟机：独立内核 + 硬件虚拟化隔离，但裁剪到最小设备集，可毫秒级恢复。

containerd 的容器运行时插件协议；CubeShim 借此把 MicroVM 伪装成普通容器。
envd

TPROXY
Linux 透明代理机制，保留原始目标地址与源 IP，CubeEgress 借此实现透明拦截。

最长前缀匹配树，eBPF 中实现网络策略的线速查找结构。

E2B
Execution & Browser Sandbox——AI 代码执行沙箱的公有云服务，CubeSandbox 兼容其 SDK/协议。
template
rootfs + 冷启动内存快照 + 探针的打包体，沙箱创建的唯一起点。
PVM
基于页表的嵌套虚拟化，让普通云服务器（无裸金属）也能跑 KVM MicroVM。
