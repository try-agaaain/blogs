# 深入理解 KV Cache：因果注意力下的推理加速秘籍

在大型语言模型风靡的今天，我们享受着流式生成带来的丝滑体验。模型逐词涌现，几乎无停顿。这背后有一项关键的推理优化技术——KV Cache。它看似简单，却将自回归生成的计算量从三次方级别大幅削减，是模型能够实时对话的基石。本文将从注意力机制的计算本质出发，深入剖析 KV Cache 的原理与意义，并说明为何我们只需缓存键（Key）和值（Value），而无需缓存查询（Query）。

---

### 1. 朴素自回归生成的计算困境

Transformer 的核心是**缩放点积注意力**。对于输入序列 \(X\)，通过三个权重矩阵 \(W_Q, W_K, W_V\) 线性投影得到查询（Query）、键（Key）和值（Value）矩阵：
\[
Q = XW_Q,\quad K = XW_K,\quad V = XW_V
\]

在**自回归语言模型**（如 GPT）中，为了防止看到未来信息，自注意力会使用**因果掩码**，使注意力矩阵呈下三角：位置 \(i\) 只能关注 \(1\) 到 \(i\)。

训练时，整个序列已知，可以并行计算。但在推理时，模型须逐个生成 token。考虑生成长度为 \(n\) 的序列，在第 \(t\) 步，输入为 \(X^{(t)} = [x_1, \dots, x_t]\)，朴素方法会为整个序列重新计算一次投影和自注意力：
\[
Q^{(t)} = X^{(t)} W_Q, \quad K^{(t)} = X^{(t)} W_K, \quad V^{(t)} = X^{(t)} W_V
\]
然后执行完整的因果自注意力得到输出矩阵 \(O^{(t)}\)。其中，只有最后一行 \(o_t\) 是预测下一个 token 所必需的，而前 \(t-1\) 行的输出 \(o_1, \dots, o_{t-1}\) 虽被计算，却只服务于过去的预测时刻，对当前毫无贡献。

更严重的是，计算 \(Q^{(t)}(K^{(t)})^T\) 不仅包含当前查询 \(q_t\) 与所有键的交互，还重复执行了所有历史查询 \(q_i\ (i<t)\) 与键 \(k_j\ (j \le i)\) 的交互——这些在它们各自的生成步骤中早已算过，且在后续步骤中既不更新，也无必要。同时，前缀 token 的 K、V 投影也在每一步被重复计算。

第 \(t\) 步需计算约 \(t^2\) 次点积，累积复杂度为 \(O(n^3)\)。当序列长度增长时，这是推理不可承受之重。

### 2. KV Cache 的洞察：Q、K、V 的角色分离

从 Q、K、V 的角色来看，问题会变得非常清晰。

在注意力计算中，输出矩阵可以视作 Q 与 K 交互后得到权重，再乘以 V。将第 \(t\) 步的完整矩阵乘法展开：
\[
O^{(t)} 
= \begin{bmatrix} o_1 \\ \vdots \\ o_{t-1} \\ \color{blue}{o_t} \end{bmatrix}
= \underbrace{\begin{bmatrix} q_1 \\ \vdots \\ q_{t-1} \\ \color{blue}{q_t} \end{bmatrix}}_{\text{Q：所有历史查询}} \times \underbrace{\begin{bmatrix} k_1^T & \cdots & k_{t-1}^T & k_t^T \end{bmatrix}}_{\text{K：所有键}} \times \underbrace{\begin{bmatrix} v_1 \\ \vdots \\ v_{t-1} \\ v_t \end{bmatrix}}_{\text{V：所有值}} = \begin{bmatrix} q_1 K^TV \\ \vdots \\ q_{t-1} K^T V \\ \color{blue}{q_t} K^TV \end{bmatrix}
\]

这里省略了 softmax 和缩放因子等非关键操作，聚焦于 Q、K、V 三者的关系。这个乘法清晰地显示：

- 输出 \(O^{(t)}\) 的每一行，是某个查询 \(q_i\) 与所有键 \(K\) 作用后，再对值 \(V\) 加权求和的结果。
- **只有最后一行**，即由 \(\color{blue}{q_t}\) 产生的输出，才是当前预测下一步所需的上下文表示 \(o_t\)。
- 前 \(t-1\) 行是 \(q_1\) 到 \(q_{t-1}\) 分别与 K 作用的结果，它们与当前预测完全无关。

因此，我们得出核心规律：**预测只关心 \(q_t\) 和前面所有 token 之间的关系，而不关心 \(q_i\ (i<t)\) 和其他 token 之间的关系。** 历史查询 \(q_1, \dots, q_{t-1}\) 在其生成的当下已完成使命，此后再无用场。

另一方面，前缀的 K 和 V 不会因新 token 而改变：
\[
K_{1:t} = \begin{bmatrix} K_{1:t-1} \\ k_t \end{bmatrix}, \quad V_{1:t} = \begin{bmatrix} V_{1:t-1} \\ v_t \end{bmatrix}
\]

以上是单层情况。**在多层的 Transformer 网络中，这一性质可以跨层传递。** 对于第 \(l+1\) 层，它的输入向量 \(x_t^{(l+1)}\) 完全由上一层的当前输出 \(o_t^{(l)}\) 经过残差连接和前馈网络得到，与其他历史输出无关：
\[
x_t^{(l+1)} = \text{LayerNorm}\big(o_t^{(l)} + \text{FFN}^{(l)}(o_t^{(l)})\big)
\]
因此，第 \(l+1\) 层当前时刻的查询、键、值仅由该输入决定：
\[
q_t^{(l+1)} = x_t^{(l+1)} W_Q^{(l+1)},\quad k_t^{(l+1)} = x_t^{(l+1)} W_K^{(l+1)},\quad v_t^{(l+1)} = x_t^{(l+1)} W_V^{(l+1)}
\]
可见，生成下一层所需的 \(q_t^{(l+1)}\) 以及新的键值对 \(k_t^{(l+1)}, v_t^{(l+1)}\) 仅仅依赖于 \(o_t^{(l)}\)，与历史输出 \(o_1^{(l)}, \dots, o_{t-1}^{(l)}\) 无关。这意味着，每一层新时刻的 K 和 V 都只由该层当前输出决定，无需保留上层的任何历史查询或输出序列。于是，为每一层单独缓存其 K、V，便足以支撑所有未来的注意力计算。

这两点洞察直接导出 KV Cache 策略：**保留对未来所有查询都有用的 K 和 V，彻底舍弃仅影响过去的历史 Q。** 我们不再计算完整的 \(Q^{(t)}\) 矩阵，也不再重复投影历史的 K、V，而是维护一个不断追加的 KV Cache。

### 3. KV Cache 的递推流程

KV Cache 的推理过程可由以下递推步骤描述：

**初始化**（\(t=1\)，给定起始 token \(x_1\)）：
\[
k_1 = x_1 W_K,\quad v_1 = x_1 W_V
\]
将 \((k_1, v_1)\) 存入缓存。随后根据上下文生成 \(x_2\)。

**递推步**（\(t \ge 2\)）：
对当前最新 token \(x_t\)，只计算其单点投影：
\[
q_t = x_t W_Q,\quad k_t = x_t W_K,\quad v_t = x_t W_V
\]
取出缓存的累积键、值矩阵：
\[
K_{\text{cache}} = \begin{bmatrix} k_1 \\ \vdots \\ k_{t-1} \end{bmatrix}, \quad V_{\text{cache}} = \begin{bmatrix} v_1 \\ \vdots \\ v_{t-1} \end{bmatrix}
\]
拼接形成当前完整键值：
\[
K_{1:t} = \begin{bmatrix} K_{\text{cache}} \\ k_t \end{bmatrix}, \quad V_{1:t} = \begin{bmatrix} V_{\text{cache}} \\ v_t \end{bmatrix}
\]
注意力前向计算仅针对当前查询 \(q_t\)：
\[
o_t = \text{softmax}\!\left( \frac{q_t K_{1:t}^T}{\sqrt{d_k}} \right) V_{1:t}
\]
然后更新缓存：
\[
K_{\text{cache}} \leftarrow K_{1:t},\quad V_{\text{cache}} \leftarrow V_{1:t}
\]
最后，\(o_t\) 经后续网络层产生第 \(t+1\) 个 token \(x_{t+1}\)。

在这一过程中，历史查询 \(q_1, \dots, q_{t-1}\) 从未被计算，也无需存储。KV Cache 的本质，就是对因果注意力逐行计算特性的精确裁剪。

### 4. 计算量与内存分析

引入 KV Cache 后，生成步骤 \(t\) 的注意力计算量骤减：只需计算 \(q_t\) 与长度为 \(t\) 的键序列的点积，复杂度为 \(O(t \cdot d_k)\)。总生成 \(n\) 个 token 的计算复杂度降为 \(\sum_{t=1}^{n} O(t \cdot d_k) = O(n^2 d_k)\)，相比朴素方法的 \(O(n^3 d_k)\) 实现了巨大飞跃。在长序列生成时，这几乎是将平方级常数砍掉了一个数量级的时间，实际感知上就是从“卡顿”变为“流畅”。

然而，代价是**显存占用**。每一层 Transformer 都需要维护自己的 KV Cache。假设模型有 \(L\) 层，每层有 \(H\) 个注意力头，每个头的键、值向量维度均为 \(d_k\)，使用半精度浮点（FP16），则长度为 \(n\) 的序列需要缓存的数据量为：
\[
\text{Mem} = 2 \times L \times H \times n \times d_k \times 2 \text{ bytes}
\]
以典型的 7B 模型为例，\(L=32\)，\(H=32\)，\(d_k=128\)，当序列长度达到 4096 时，KV Cache 将占用约 2×32×32×4096×128×2 字节 ≈ 2 GB。当并发请求增多或序列变长（如 128K 上下文）时，缓存显存会成为严重瓶颈。因此，KV Cache 既是天使亦是魔鬼——它带来了计算效率，同时也对存储和内存管理提出了新挑战。

### 5. 来自 KV Cache 的进化：压缩与分页

正是由于 KV Cache 的重要性与显存压力，业界发展出多种优化策略，这里简述几个方向以体现技术脉络：

- **多查询注意力（MQA）与分组查询注意力（GQA）**：传统多头注意力中，每个头都有独立的 K、V 投影，导致缓存头数多。MQA 让所有头共享同一组 K、V，大幅削减缓存量；GQA 则将头分组，组内共享 K、V，在效果和效率间取得平衡，已被 Llama 2、Mistral 等广泛采用。
- **PagedAttention 与 vLLM**：受操作系统虚拟内存分页启发，将连续的 KV Cache 切分为固定大小的“页”（Block），请求可按需非连续存储，显著降低碎片化并提升吞吐量。这彻底改变了 LLM 推理服务的内存管理方式。
- **FlashAttention**：通过 IO 优化的精确注意力算法加速计算，可直接与 KV Cache 结合使用，在硬件级进一步提升效率。
- **量化缓存**：将缓存的 K、V 量化为 INT8 或 FP8，减少显存占用，同时保持精度。

这些进化无不围绕着同一个核心：KV Cache 是推理效率的杠杆，任何对其量级的压缩或对访问模式的优化都能直接转化为成本降低与速度提升。

### 6. 结语

KV Cache 并非神来之笔的奇技淫巧，而是从注意力机制和自回归生成的本征属性中推导而出的必然优化。它精准地捕捉到一个事实：在逐 token 生成的因果注意力中，历史键值对是未来所有预测的共享上下文，而历史查询却是已完成使命的“过客”。存储该存的，丢弃无用的，正是这一简洁的理念，支撑起了当今大语言模型实时交互的骨架。理解 KV Cache，不仅是理解一项加速技术，更是深入认识 Transformer 推理行为的钥匙。随着模型上下文长度向百万 token 进发，KV Cache 的存储与访存优化仍将是系统优化的主战场，而它背后的“只关心 \(Q_t\)”原则，会持续指导我们设计更高效、更聪明的推理引擎。
