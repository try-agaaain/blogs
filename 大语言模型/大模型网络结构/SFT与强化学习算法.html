01为什么 SFT 还不够？

SFT（Supervised Fine-Tuning，监督微调）是用人工标注的高质量「指令-回答」对，对预训练大模型做有监督交叉熵训练，让模型学会"像人一样回答"。它的训练目标很简单：

SFT 训练目标（最大化答案的对数似然）
\[ \mathcal{L}_{\text{SFT}}(\theta) = - \mathbb{E}_{(x, y) \sim \mathcal{D}} \Big[ \sum_{t} \log p_\theta(y_t \mid x, y_{<t}) \Big] \]

模型只要"照着抄"标注数据，回答得越像标注越好，并不关心结果是否真的被用户喜欢。

SFT 的三个局限

  • 只会模仿，不会优化：SFT 是回归式的模仿学习，模型从未见过"惩罚"，因此无法学会主动放弃差回答、追求更好结果。
  • 缺乏对"偏好"的建模：标注数据通常是单条的，无法表达"回答 A 比回答 B 好多少"，难以对齐人类的主观偏好。
  • 难以处理长程推理：每一步生成都按交叉熵监督，缺少对整个回答"好坏"的全局信号，复杂任务（数学、代码）容易半途而废。
核心认知：SFT 解决"模型会说人话"，强化学习解决"模型把话说好"——它用奖励信号告诉模型什么是对的，再让模型自己去探索如何最大化奖励，这是 SFT 做不到的。

关键：RM 给 RL 提供「老师」

奖励模型（Reward Model）通过对回答对 \(y_w \succ y_l\)（好回答胜于差回答）的偏好数据进行二分类训练，学会给任意回答打一个标量分数 \(r_\theta(x, y)\)。RL 阶段就靠这个分数当"反馈信号"。

奖励模型训练目标（Bradley–Terry 偏好模型）
\[ \mathcal{L}_{\text{RM}} = - \mathbb{E}_{(x, y_w, y_l)} \Big[ \log \sigma\big( r_\theta(x, y_w) - r_\theta(x, y_l) \big) \Big] \]
提示：很多新一代方法（DPO / GRPO）不再单独训练 RM，而是绕过 RM 直接用偏好数据或组内相对分数优化策略，这就是后面要讲的"无 RM 流派"。

03强化学习核心概念速览

把语言生成看成一个序贯决策过程：模型每生成一个 token，就是做出一次「动作」，之前生成的内容是「状态」，RM 的打分是「奖励」。先建立这些基础术语：

策略 \(\pi_\theta(a \mid s)\)
模型本身。给定当前序列（状态）预测下一个 token（动作）的概率分布，\(\theta\) 是要优化的参数。
状态 \(s\) / 动作 \(a\)
状态 = 已生成的 token 序列；动作 = 选下一个 token。整条序列组成一条「轨迹」。
奖励 \(r\)
对单步或整段回答的打分。LLM 中通常只在序列末尾给一个整句分数 \(R(x,y)\)。
回报 \(G_t\)
从 t 时刻起累计的（折扣）奖励总和。它告诉我们"这一步决策到底值多少"。
优势函数 \(A(s,a)\)
"这一步比平均好多少"：\(A = Q(s,a) - V(s)\)。是策略梯度算法的核心，越大说明该动作越值得强化。
KL 散度 \(\mathrm{KL}\)
衡量当前策略与参考策略（通常是 SFT 模型）的差异。RL 时要加惩罚项，防止模型"奖励黑客"式地乱说话。
策略梯度
通过「好动作提概率、差动作降概率」的方向更新：\(\nabla_\theta J = \mathbb{E}[A \cdot \nabla_\theta \log \pi_\theta]\)。
参考策略 \(\pi_{\text{ref}}\)
RL 开始前的 SFT 基线模型。KL 惩罚项就是让新策略不要偏离它太远。
为什么必须加 KL 惩罚？如果只最大化奖励，模型会钻空子——输出一堆冗长、奉承、甚至乱码来"骗高分"（奖励黑客，Reward Hacking）。加上 \(- \beta \cdot \mathrm{KL}(\pi_\theta \| \pi_{\text{ref}})\) 项后，模型必须在"高分"与"不偏离常识"之间取得平衡。

04PPO · 强化学习的"标准答案"

PPO（Proximal Policy Optimization，近端策略优化）由 OpenAI 提出，是 InstructGPT 的默认算法，也是 RLHF 最经典的实现。它属于在线策略 + 值函数一派的代表。

核心思想：新老策略对比，稳住更新步长

PPO 用"重要性采样"把旧策略采到的样本复用于新策略，并用一个 clip 裁剪限制每一步更新幅度——如果新旧策略差异超过 \(\varepsilon\) 就把它截断，从而保证训练稳定。

PPO-Clip 目标 + KL 惩罚（LLM 版）
\[ \mathcal{L}_{\text{PPO}} = \mathbb{E}_{t} \Big[ \min\big( \rho_t \, \hat{A}_t,\; \mathrm{clip}(\rho_t,\, 1-\varepsilon,\, 1+\varepsilon) \, \hat{A}_t \big) \Big] - \beta \, \mathrm{KL}(\pi_\theta \| \pi_{\text{ref}}) \]
其中重要性比率 \(\rho_t = \dfrac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{old}}(a_t \mid s_t)}\)，\(\hat{A}_t\) 是 GAE 估计的优势值。
需要的模型
4 个：Actor（策略）＋ Critic（价值网络）＋ Reference（参考）＋ RM（奖励）
优势估计
GAE 优势，靠 Critic 价值网络 \(V(s)\) 提供基线
优点
稳定、通用，是大量闭源/开源模型对齐的黄金标准
缺点
在线采样 + 4 个模型常驻显存，训练开销极大
一句话总结：PPO = 用"旧样本重复利用 + 裁剪限制步长 + 价值网络降方差"三件套，让 RL 训练既稳又高效——代价是要背上 Critic 这个大包袱。

05GRPO · 丢掉 Critic 的轻量派

GRPO（Group Relative Policy Optimization，组相对策略优化）由 DeepSeek 提出，因 DeepSeek-R1 而爆红。它观察到一个事实：价值网络 \(V(s)\) 既难训练又耗显存，于是干脆把它扔掉——用"组内多个采样结果的相对水平"来代替价值网络提供基线。

核心思想：组内平均代替价值网络

对同一个问题 \(q\) 采样 \(G\) 个回答（一个 group），算出各自的奖励后做标准化，得到组内优势：回答比组内平均好多少。所有采样、打分、标准化都是自监督的，不需要额外的 Critic。

GRPO 目标（组内优势 + 显式 KL）
\[ \mathcal{L}_{\text{GRPO}} = \mathbb{E}\Big[ \frac{1}{G} \sum_{i=1}^{G} \min\big( \rho_i \, \hat{A}_i,\; \mathrm{clip}(\rho_i,\, 1-\varepsilon,\, 1+\varepsilon) \, \hat{A}_i \big) \Big] - \beta \, \mathbb{E}[\mathrm{KL}]\ \ \text{,}\quad \hat{A}_i = \frac{r_i - \text{mean}(\mathbf{r})}{\text{std}(\mathbf{r})} \]
需要的模型
3 个：Actor ＋ Reference ＋ RM（无 Critic）
优势估计
组内奖励 z-score 标准化，无价值网络
优点
省一半左右显存，工程简单，R1 大规模验证有效
缺点
组内样本方差大时基线有偏；离线/无采样场景不适用
一句话总结：GRPO = "采样 N 个答案，比一比谁更好"——把价值网络省掉，用组内相对分数当优势，性价比极高的 PPO 替代方案。

06DPO · 不需要 RL 的"偏好直调"

DPO（Direct Preference Optimization，直接偏好优化）把"先训 RM、再跑 RL"的两阶段过程，数学上化简为一个简单的二分类损失。它把 RL 目标闭式解回代进损失函数，于是完全不需要 RM、不需要在线采样、也不需要 Critic。

核心思想：偏好数据直接调参

对于一对偏好数据（好回答 \(y_w\)、差回答 \(y_l\)），DPO 让策略在"做得好的地方更像参考模型、做得差的地方偏离参考模型"。凡是当前策略更偏好好回答、厌恶差回答，损失就小。

DPO 损失（把 RLHF 目标变成分类损失）
\[ \mathcal{L}_{\text{DPO}} = - \mathbb{E}_{(x,y_w,y_l)} \Big[ \log \sigma\Big( \beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)} \Big) \Big] \]
需要的模型
2 个：Policy ＋ Reference（无需 RM / Critic）
训练方式
离线小批量梯度下降，像普通 SFT 一样稳定
优点
实现简单、稳定、省显存，社区最爱
缺点
无在线探索；对偏好数据质量敏感；理论上仍是"隐式 KL 约束"
DPO 的定位：它本质上是把 RLHF 的数学结构"翻译"成了监督式损失，所以在许多场景（特别是数据量适中、需要快速上线时）效果与 PPO 相当，却便宜得多。这也是为什么现在很多项目直接"跳过 RL 跑 DPO"。

07其他值得一提的算法

RLOO

REINFORCE 改良

RLOO（REINFORCE with Leave-One-Out）是最朴素的策略梯度算法 REINFORCE 的现代改良版。对同一个问题采样一组回答，把"本回答的奖励 - 组内其他回答的平均奖励"作为优势，也就是用"组内留一平均"当基线。

RLOO 优势（组内留一基线）
\[ \hat{A}_i = r_i - \frac{1}{G-1} \sum_{j \neq i} r_j \]
特点
最简单直观的策略梯度，无 Critic、无裁剪
优点
代码量小、易复现，是理解 RL 的最佳起点
缺点
方差仍较大，收敛不如 PPO/GRPO 稳

KTO

单样本偏好

KTO（Kahneman–Tversky Optimization）不需要成对的"好 vs 差"数据，只需要单独标注"这个回答好不好"（参考前景理论，人对损失更敏感）。它用 \(r_\theta(x,y) = \beta \log \frac{\pi_\theta(y\mid x)}{\pi_{\text{ref}}(y\mid x)}\) 与阈值 0 比较，好回答推到 0 以上、坏回答压到 0 以下。

数据要求
仅需单条质量标注（非成对），数据更容易获取
优点
贴近真实标注场景（很多数据只有"好不好"没有"谁更好"）
缺点
对"好/坏"阈值敏感，调参略麻烦

ORPO

SFT + 偏好一体

ORPO（Odds-Ratio Preference Optimization）把 SFT 和偏好对齐合并到一次训练中：在普通交叉熵损失之外，额外加一项"几率比（Odds Ratio）"惩罚，让模型对好回答的概率相对差回答上升。它连参考模型都不需要。

需要的模型
仅 1 个：Policy 自身
优点
两阶段变一阶段，省一次完整训练，无需参考模型
缺点
同时优化两个目标可能相互干扰，稳定性略逊

SimPO

DPO 精简版

SimPO（Simple Preference Optimization）把 DPO 进一步简化：去掉参考模型，改用回答长度的平均对数概率作为隐式奖励，并引入长度归一化，缓解 DPO 的"偏爱短回答"偏差。

需要的模型
仅 1 个：Policy 自身
优点
更省显存，长度归一化让长短回答更公平
缺点
无参考模型约束，需谨慎处理过拟合

09实践选型建议

不同场景的最佳选择差异很大，一个实用的决策思路如下：

场景 A · 追求极致上限
目标：数学/代码等需要强推理的对齐。
建议：PPO，预算充足且有高质量 RM。
场景 B · 复刻 R1 式推理
目标：RL 驱动的推理能力提升。
建议：GRPO，参考 DeepSeek-R1 的成熟路线。
场景 C · 有偏好数据、想快速对齐
目标：通用对话对齐、安全价值观。
建议：DPO，离线稳定、效果可观。
场景 D · 数据只有"好坏"标注
目标：标注成本受限。
建议：KTO，单样本偏好即可训练。
场景 E · 想从 SFT 一步到位
目标：最小改动、省训练轮次。
建议：ORPO / SimPO，SFT 阶段顺手完成对齐。
场景 F · 入门学习
目标：理解策略梯度本质。
建议：RLOO，代码最短、概念最纯。
